## Behaviour

- **Account**: `account` is required. Empty, unknown, control-bearing, or
  over-long ids are refused with `mail_account_unknown` **before any credential
  lookup or socket**; the active account is never substituted.
- **Provider**: only `outlook` and `imap` are supported, checked against the
  `emlExport` capability and the account's refusals. Gmail/Hey/JMAP →
  `mail_export_unsupported` with no fetch and no file.
- **Message id**: `<uid>:<folder>` is validated before provider work. Duplicate admission uses the parsed canonical form, so `01:INBOX` and `1:INBOX` share one account/message slot; the returned identity remains the captured request id.
- **Bytes**: taken from E01's `imap.rawMessage` (`EXAMINE` + `BODY.PEEK[]`, one
  literal, unsolicited UIDs ignored) and written unchanged.
- **Limit**: 25 MiB. Raw retrieval passes `MAX_BYTES` to the IMAP framing layer, which refuses an over-limit announced literal before allocating its payload buffer or reading its octets. The existing 32 MiB aggregate response bound remains in force. The base64 length is checked before decoding, then the decoded length is checked again.
- **Filename**: built from the untrusted `suggestedName` — basename only,
  controls/separators dropped, capped to 240 bytes, `.eml` appended once,
  `message.eml` fallback.
- **Write**: `create_dir_all(Downloads)`, then exclusive `create_new` with mode
  `0600` and `O_NOFOLLOW`; `write_all` + `sync_all`; the partial file is removed
  on any write/flush failure; collisions get ` (n)` rather than overwriting. On
  Windows the same is done through `platform::private_fs`.
- **Retained path**: the result carries the actual `path`, `filename`, and byte
  count after a committed write.
- **Admission/deadline**: one active export per account and at most two overall; duplicate account/message requests are refused rather than queued. Permit waits and fetch share a 25-second operation deadline, below the client's 30-second bridge deadline. The Unix writer checks cancellation and the deadline before every exclusive-create attempt, including collision retries.
- **Cancellation**: dropping the export future signals cancellation and stops its provider fetch before the commit point. An input error makes the protocol scheduler drop pending futures; clean stdin EOF or `system.quit` drains accepted work, preserving send-then-half-close-stdin. Unix stdio polls stdout for closure as well as stdin for input, so closing all pipes during FETCH is detected before a response write. Cancellation/deadline checks apply up to successful exclusive creation; the synchronous write/fsync then completes, with cleanup on failure and success returned after a complete write.

## Tests (focused)

`src/mail/export.rs` unit tests: safe/one-`.eml` filenames (Unicode, empty, `..`,
control, path-like, over-long); duplicate names never overwrite; a symlink target
is never followed and the new file is mode `0600`; a missing/`invalid` base64
payload is `mail_export_incomplete`; an over-limit payload is refused before
decoding; a committed export reports the exact path/filename/bytes with matching
file contents; an unsupported provider is refused with the directory untouched.

`src/backend/mail_action_tests.rs` and the REST of the suite stay green; the
contract runner executes the new unreleased case.

## Security verdict

Scope: the new backend export path, on Linux, exercised by the tests above.

- **Account/identity confusion** — PASS. Strict, explicit resolution; no active
  fallback; unsupported providers refused before any fetch.
- **Filesystem** — PASS (Unix). Exclusive creation, `0600`, `O_NOFOLLOW`, no
  overwrite, partial cleanup on failure; symlink target untouched. Windows path
  uses the platform primitives but is **NOT VERIFIED** at runtime here.
- **Resource bounds** — PASS for the tested Linux path. The 25 MiB literal ceiling is enforced at its length announcement, before payload allocation/read, and encoded/decoded checks remain in place. The aggregate IMAP response stays capped at 32 MiB. Admission canonicalizes UID spelling, concurrency is bounded to one active export per account and two overall, and the Unix writer rechecks cancellation/deadline on every collision attempt. Protocol errors cancel pending work; clean EOF/quit drains it. See the regression coverage below for the distinction between scheduler tests and process tests.
- **Secret handling** — PASS. Credentials are resolved inside the IMAP layer as
  for every other provider call; none is logged, returned, or placed in the
  result. The result carries only ids, path, filename, and byte count.
- **Partial files** — PASS. No partial `.eml` survives a write failure; a
  committed file is never reported as a failure.
- **Not verified**: a real 25 MiB message over a live server, macOS/Windows
  runtime, and live-account export (requires credentials and is out of scope).

Claim: the desktop export path is PASS for the tested boundaries; cross-platform
runtime is NOT VERIFIED.

| Regression | Observed boundary |
| --- | --- |
| `disconnect_cancels_accepted_work_instead_of_draining_it` | Scheduler drops accepted pending work and emits no response when the input-error cancellation flag is set. This unit test does not itself close real stdio pipes during FETCH. |
| `equivalent_ids_share_one_admission_slot` | Concurrent `01:INBOX` / `1:INBOX` requests produce one successful export, one `mail_export_in_flight` refusal, and one file. |
| `a_collision_does_not_bypass_an_expired_deadline` | An expired deadline with an existing first-choice filename returns `request_timed_out` and creates no additional file. The per-retry check is also present inside the Unix create loop. |
| `raw_message_refuses_an_over_limit_literal_before_reading_it` | A server announces a 25 MiB + 1 literal without sending its payload; retrieval returns `mail_export_too_large`. |

The existing real-process `tests/stdio.rs` checks cover broken output with stdin left open, fragmented input followed by clean EOF, and draining accepted requests before quit. The eager stdout poll is the implementation change for the close-all-pipes mid-FETCH scenario; the four new tests above do not constitute an end-to-end reproduction of that exact scenario.

The Windows writer delegates collision handling to `platform::private_fs::write_unique` after a single cancellation/deadline check, and Windows stdin does not use the Unix eager stdout poll. The per-retry and eager-disconnect claims here are scoped to Unix source and tested Linux behavior; Windows runtime remains NOT VERIFIED.
