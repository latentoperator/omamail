# E01 evidence — exact original message bytes

Status: **READY FOR REVIEW**. Task: E01. Base: `b730830` (E00 branch tip).
Branch: `task/E01-raw-message`. Depends on the E00 contract (`planning/decisions/E00.md`).

Adds the native raw-retrieval operation only. It is **not** wired to
`mail.exportEml` and is not reachable from QML: no storage, no RPC surface, no
capability declaration (those are E02).

## What was added

- `src/providers/imap/export.rs` — an internal provider operation
  `imap.rawMessage` that returns the server's literal octets unchanged.
  - `EXAMINE` selects the mailbox read-only and `UID FETCH <uid>
    (UID BODY.PEEK[])` requests the body, so `\Seen`, flags, and message
    location are untouched and no `STORE`/`MOVE`/`EXPUNGE` is ever issued.
  - `single_literal()` takes exactly one literal for the requested UID from the
    framed response; an unrelated unsolicited UID is ignored, and `NIL`, a
    missing record, or two literals for the requested UID are refused.
  - Result: `{"bytes": <len>, "data": <base64>}`. Base64 is the provider
    boundary's existing convention (`imap.request`, `attachment.read`); E02
    decodes and writes it without the bytes ever reaching QML.
- `src/providers/imap/mod.rs` — `mod export;`; `export::validate` is run before
  any credential lookup or socket; `imap.rawMessage` is routed in `execute` and
  included in the `cancel::run` set so `imap.cancel` cancels it.
- `src/providers/imap/read.rs` — `Node`, its accessors, and `nodes()` become
  `pub(super)`, the narrowly shared parsing helper E00 §1 identified.

`imap.rawMessage` is deliberately **absent from `src/backend/methods.rs`** (the
advertised inventory), like the internal `jmap.action*` planners. The inventory
is unchanged, so `check-api` and the binary's advertised method list are
unaffected. QML is forbidden by `tests/test_source.sh` from calling an
undeclared method anyway.

## Identity and validation

`export::validate` rejects a malformed folder (quoting/controls) or a `uid` that
is absent, zero, or out of `u32` range with `mail_export_message_invalid`
**before any connection opens** (asserted by a test). Provider/account
resolution and the strict no-active-account-fallback rule belong to E02, which
supplies the resolved settings this operation consumes.

## Error strings (E01 level → E00 boundary)

| E01 | E00 `mail.exportEml` |
| --- | --- |
| `mail_export_message_invalid` | `mail_export_message_invalid` |
| `mail_export_message_missing` (missing record or `NIL`) | `mail_export_message_missing` |
| `mail_export_incomplete` (duplicate literal) | `mail_export_incomplete` |
| `imap_command_failed` (tagged NO/BAD) | provider failure |
| `mail_response_too_large` (literal/response over the 32 MiB `LIMIT`) | `mail_export_too_large` |
| `mail_network_failed`, `imap_invalid_response` | provider failure |

E02 owns the final mapping and the 25 MiB product limit (below the transport's
32 MiB bound).

## Tests (`src/providers/imap/tests.rs`, synthetic loopback server)

| Test | Proves |
| --- | --- |
| `raw_message_returns_exact_octets_and_only_peeks` | bytes returned **byte-for-byte**: CRLF, folded header, `\xc3\xa9`, `\x00`, `\xff`, and a payload that imitates a tagged completion and another FETCH record; the only data command is `UID FETCH 1 (UID BODY.PEEK[])` after `EXAMINE` |
| `raw_message_ignores_unsolicited_and_other_uids` | an unrelated `UID 999` FETCH is ignored; the requested UID's bytes are returned |
| `raw_message_refuses_missing_nil_and_duplicate_bodies` | `NIL` → missing; other-UID-only → missing; two literals for the requested UID → incomplete |
| `raw_message_refuses_a_non_ok_completion` | tagged `NO` → `imap_command_failed` |
| `raw_message_rejects_a_bad_uid_before_connecting` | `uid:0` is refused with no connection opened |
| `cancelling_a_raw_message_read_stops_the_work` | `imap.cancel` drops the in-flight fetch and returns `request_cancelled` |
