# E00 decision — export contract, capabilities, and limits

Status: **READY FOR REVIEW** — decisions confirmed by the owner on 2026-09-29
(§6); supervisor sign-off on the frozen record still required before E01/E02.
Task: E00. Base: `d88833e` (main after F00). Branch: `task/E00-export-contract`.
Owner-authorized reading only; no production export code was written.

This record traces the current path, freezes the `mail.exportEml` contract, and
records four values that differ from the plan's proposal. All file/line
references are to this base.

## 1. Traced path today (auth → IMAP → resource)

- Dispatch: `src/backend/mod.rs:66` routes `mail.list|read|act|send` to
  `Session::mail_call`; `src/backend/mail.rs:340-367` matches those four and
  returns `unknown_method` for anything else. A new method must be added in both
  places.
- Domain: `mail.read` builds `ReadRequest { account, id }` (`src/mail/types.rs:110`)
  and calls `crate::mail::read::read_with` (`src/mail/read.rs:243`), which calls
  the provider adapter `reader.open` and then projects a safe reader. **The
  reader never keeps the raw bytes** — it parses them into a display projection.
- Provider: `ProviderRead` (`src/backend/mail.rs:14`) forwards to
  `imap.read`, which lands in `src/providers/imap/read.rs`.
- Wire: `messages()` (`src/providers/imap/read.rs:694`) issues
  `UID FETCH {set} (UID FLAGS INTERNALDATE RFC822.SIZE BODY.PEEK[{section}])`
  (line 755), with `section=""` for a full fetch. Response framing lives in
  `src/providers/imap/mod.rs` (`nodes`, literal handling at 161-186);
  `command()` (line 193) returns the whole response as `Vec<u8>`.
- **Raw literal extraction point:** `parse_messages()` (`read.rs:649`) records
  `raw = Some(value.text())` for a `BODY[...]` field (line 682) — `Node::text()`
  returns the literal octets — then immediately calls
  `crate::message::parse(raw)` (line 689) and **discards `raw`**. E01 must retain
  exactly these octets for the requested UID; parse-then-reserialize is not an
  acceptable byte source.
- Account resolution: `src/mail/account.rs:3` `resolve_account("")` **falls back
  to the registry's `activeId`**. The plan (§3.2) forbids that for export. Export
  must resolve strictly (non-empty id, exact registry match) and never reuse the
  fallback.

## 2. Cancellation and deadlines

- Per-request cancellation: `src/providers/imap/cancel.rs`. Key is
  `(accountId, requestToken)`; `cancel()` sets a flag and notifies; `run()` races
  the future and returns `request_cancelled`; entries are retained 60 s and
  capped at 1024. `imap.cancel` is the entry point.
- RPC deadline: `REQUEST_TIMEOUT = 25 s` (`src/backend/protocol.rs:15`), and every
  frame is tagged `now + 25 s` (`protocol.rs:42,62`). But it is only *enforced*
  with `timeout_at` for `gmail.*` and `request.upload` of gmail methods
  (`src/backend/rpc.rs:120-127`); every other method, including `mail.*`, is
  dispatched with **no RPC-level timeout**, the 25 s acting only as a
  pre-dispatch expiry check (line 113). Mail operations therefore own their
  deadlines, and IMAP already uses **22 s** inner timeouts
  (`src/providers/imap/mod.rs:397,445,491`).
- Client deadline: the QML bridge fails a request after **30 s**
  (`ui/backend/Backend.qml:110-111`; 65 s for `agent.context`). This is the real
  outer bound a user experiences.
- **Consequence:** `mail.exportEml` must enforce its own deadline inside the
  operation (as `mail.read` does) and finish under the client's 30 s. The frozen
  value is **25 s** (§6 O2), leaving about 5 s for the reply to be written.
- Other bounds: IMAP response `LIMIT = 32 MiB` (`imap/mod.rs:21`); protocol
  `MAX_RESPONSE = 64 MiB` (`protocol.rs:12`); attachment payload
  `MAX_BYTES = 20 MiB` (`attachment/mod.rs:13`).

## 3. Storage, Downloads, and filenames

- Downloads root: `crate::platform::dirs::AppDirs::discover()?.downloads`
  (`src/platform/dirs.rs:18`), resolved from `XDG_DOWNLOAD_DIR`, then
  `user-dirs.dirs`, then `~/Downloads`; the value must be absolute
  (`dirs.rs:171`). `AppDirs::discover` itself validates every root is absolute
  and parent-free.
- Existing writer to reuse as a model: `attachment::write_unique`
  (`src/attachment/mod.rs:225`) — `create_new(true)` (exclusive, never
  overwrites), mode `0600`, `O_NOFOLLOW`, `write_all` + `sync_all`, and
  `remove_file` of the partial on failure; collision suffix is
  `stem (n).ext` for n in 1..1000. `attachment::store` (line 192) resolves
  Downloads and `create_dir_all`s it. Attachment `MAX_BYTES` (20 MiB) is lower
  than the export limit, so export needs its own bounded writer rather than the
  attachment payload/RPC route.
- Filename policy model: `attachment::safe_filename` (`attachment/mod.rs:15`) —
  basename only (strips `/` and `\`), control chars to `_`, trims, `attachment`
  fallback, 240-byte cap preserving the extension.

## 4. Frozen contract

**Method:** `mail.exportEml` (provider-neutral; Outlook and generic IMAP only).

**Params**

```json
{"account":"outlook:person@example.test","id":"42:INBOX","suggestedName":"Project update"}
```

- `account` — **required, non-empty**; exact registry id; unknown →
  `mail_account_unknown`. No active-account fallback, no control characters,
  bounded length.
- `id` — **required**, `"<uid>:<folder>"` (see `message_id`, `imap/read.rs:577`).
  Empty/unknown account or malformed id is rejected before any credential lookup
  or network work.
- `suggestedName` — optional, untrusted display hint; never a path.
- No output-directory, format, provider-URL, or credential parameters.

**Result**

```json
{"accountId":"outlook:person@example.test","messageId":"42:INBOX",
 "path":"/home/u/Downloads/Project update.eml","filename":"Project update.eml","bytes":12345}
```

**Errors** (`Err("invalid_params")` maps to -32602; every other string to -32000
with the string as the message — `src/backend/rpc.rs:137`)

| Condition | message | JSON-RPC code |
| --- | --- | --- |
| malformed types / extra fields | `invalid_params` | -32602 |
| empty or unknown account | `mail_account_unknown` | -32000 |
| provider not Outlook/IMAP | `mail_export_unsupported` | -32000 |
| malformed uid/folder | `mail_export_message_invalid` | -32000 |
| requested message absent / NIL body | `mail_export_message_missing` | -32000 |
| announced literal above the limit | `mail_export_too_large` | -32000 |
| truncated or ambiguous literal | `mail_export_incomplete` | -32000 |
| write/flush/commit failure | `mail_export_write_failed` | -32000 |
| cancelled before commit | `request_cancelled` | -32000 |
| operation deadline reached before commit | `request_timed_out` | -32000 |
| method absent on the connected binary | `backend_needs_update` | -32012 |

**Capability and identity**

- Provider capability name: **`emlExport`**, exposed through the shared provider
  mapping and QML projection (not scattered provider-id checks).
- Method presence is checked independently of the API number: the method is named
  in `backend-api.json` under `methods` and under `unreleased.methods`, and
  `ui/backend/Compatibility.js::unreleasedRefusal` returns
  `{-32012,"backend_needs_update"}` when the connected binary lacks it. A feature
  must gate on method support, not on `apiVersion` alone.

**Limits and concurrency** (values — see §6 decisions)

| Knob | Value | Basis |
| --- | --- | --- |
| raw message size | **25 MiB** | below IMAP `LIMIT` 32 MiB; above attachment 20 MiB |
| in-flight per account | **1** | duplicates for the same account/message refused |
| in-flight global | **2** | bounded, below the 4 used by `messages()` |
| operation deadline | **25 s**, enforced inside the export | under the client's 30 s bridge deadline; honours no partial file |

**Storage and completion**

- Write under `AppDirs::downloads` using a bounded writer modeled on
  `write_unique`: exclusive `create_new`, `0600`, `O_NOFOLLOW`, `write_all` +
  `sync_all`, remove the partial on any failure. Never overwrite an existing
  file; on collision append ` (n)` before `.eml`.
- Filename: apply the `safe_filename` policy to `suggestedName`, strip separators
  and control characters, refuse platform-reserved forms, fall back to
  `message`, and append `.eml` exactly once (never double up an existing `.eml`).
- **Cancellation commit point:** cancellation is honoured up to the exclusive
  create; once bytes are written and fsynced the operation **returns success**
  with the real path. A cancel that loses the race must not report both failure
  and a committed file.
- Success is emitted only after a complete, committed file; the result reports
  the actual filename, directory, and byte count. Unsigned/raw errors never reach
  the UI; existing safe error strings are reused.

## 6. Decisions (supervisor confirmed 2026-09-29)

- **O1 — param names: `account` + `id`.** Matches every sibling `mail.*` method
  (`src/mail/types.rs:236,268`). `suggestedName` is the optional display hint.
- **O2 — deadline: 25 s**, enforced *inside* the export operation (the RPC layer
  does not bound `mail.*`; see §2). It sits under the client's 30 s bridge
  deadline (`ui/backend/Backend.qml:110`), leaving room for the reply. Reaching it
  returns `request_timed_out` and must leave no partial file.
- **O3 — raw size limit: 25 MiB**, below the 32 MiB IMAP response bound and above
  the 20 MiB attachment limit.
- **O4 — concurrency: 1 per account, 2 global**, enforced with a semaphore in the
  new domain service.

E01 and E02 are gated on this record. A change to the method name, params,
result shape, or error table is a contract revision and needs a new judgment.
