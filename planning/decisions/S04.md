# S04 decision — spelling settings, persistence, and graceful absence

Status: **READY FOR REVIEW**. Task: S04. Base: `f485bf4` (the S02 branch tip,
`task/S02-spelling-menu`; S03 was deferred this pass). Branch:
`task/S04-spelling-settings`.

S04 turns the S01 temporary inputs into persisted settings, stores the
app-owned personal dictionary, and explains absence instead of failing.

## 1. What S04 adds

| Concern | Before (S02) | After (S04) |
| --- | --- | --- |
| Enabled / language | ComposeView defaults (`true`, `"en_US"`), lost on restart | Manifest-schema settings, persisted by the shell |
| Personal words | ComposeView-local list, session-only | Service-owned `spelling.json`, survives restart |
| Availability | Computed inside ComposeView only | Service-level Sonnet probe, shown in Settings |
| Settings UI | none | "Spelling" section in SettingsPage |

## 2. Decisions

| # | Decision |
| --- | --- |
| D1 | `spellingEnabled` (boolean, default on) and `spellingLanguage` (string, `"en_US"`) live in the manifest schema and persist through the shell like `suggestEvents`. |
| D2 | Personal words are app-owned and stored in a private `spelling.json` beside `window.json`, never in a global Sonnet/Hunspell dictionary. Add is idempotent; remove exists for future UI. |
| D3 | Availability is a Service-level probe (a Loader over the same `SpellcheckAdapter`), kept separate from the requested `spellingEnabled`. The Settings page explains a missing module or dictionary; it never silently substitutes a language. |
| D4 | The enabled toggle stays usable when the dictionary is missing: the request is persisted even before the dictionary is installed; the underline simply does not appear until it is. |

## 3. Dependency guidance

Spell-checking is optional and local:

- **Sonnet QML module** (`org.kde.sonnet`, the KDE spell-checking framework) is
  imported only by `ui/compose/SpellcheckAdapter.qml`, which is always loaded
  through a Loader. Without it the composer still opens; `spellingStatus` reads
  `no-module`.
- **Hunspell dictionary** for the requested language — `hunspell-en_us` for the
  `en_US` default (Arch: `pacman -S hunspell-en_us`; Ubuntu: `hunspell-en-us`).
  Without it `spellingStatus` reads `no-dictionary` and the Settings page names
  the package to install.
- Neither is a hard dependency: a machine with neither still composes, edits,
  and sends. Checking is local — no network or model calls.

## 6. Review risks and limitations

- The `spelling.json` write goes through `writeConfig` (the same config-store
  host helper as `window.json`); the file round-trip is not exercised in the
  bare QML test harness (no host process), only the in-memory store and the
  parse/normalise path are. The write path is shared with `window.json`, which
  is covered elsewhere. A failed write is best-effort: the word stays in memory
  for the session and is retried on the next change, but is not surfaced as an
  error (there is no compose-time error channel for a dictionary write, and the
  consequence is only a word re-flagged after restart).
- The availability probe loads Sonnet in the service process (one extra,
  lightweight highlighter), independent of any compose window.
- "Default on when available" means the setting defaults to on and the underline
  appears only when the probe reports `ready`; the two facts are kept distinct
  rather than conflated into one flag.
