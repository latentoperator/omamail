# S01 decision — body underlines, drawn by the composer

Status: **IN PROGRESS** — implementation landed for hands-on tuning; the formal
handoff follows once the look and behaviour settle. Task: S01. Base: `8692d4d`
(the S00 branch tip; S00 is not yet merged). Branch: `task/S01-body-spelling`.

This record updates the S00 adapter contract and supersedes S00 decision **D1**.
It is the working agreement for S01 until superseded by the handoff.

## 1. Why D1 changed

S00 §2.2 found that Sonnet's `misspelledColor` has no effect on the rendered
underline. S01 found the larger problem: Sonnet's **QML** highlighter also sets
`errorFormat.setForeground(spellColor)`, so a misspelled word is drawn in red
*text* as well as a red underline. The **QWidget** highlighter
(`src/ui/highlighter.cpp`) sets only the underline style and colour — the red
foreground is specific to the QML one, and 6.29.0 is the newest Arch package.

Owner decision (2026-09-29): **underline only**, so the composer draws the
underline itself and Sonnet's highlighter never paints.

## 2. Decisions confirmed by the owner (2026-09-29)

| # | Decision |
| --- | --- |
| D1′ | The composer draws the underline; Sonnet's highlighter stays `active: false` and is used only as a checker. Supersedes S00 D1 (accept Qt's red). |
| D1c | The underline colour is the theme's error/urgent role (`Color.urgent`), passed to the composer as `errorColor`. |
| D2′ | A word is marked only once it is **finished** — when a delimiter follows it. A word still being typed is never underlined. |
| D3′ | Suggestions live in a slim inline strip under the body, coloured from the composer's theme roles and font. |

D2 (app-owned personal words via `ignoreWord`) and D3 (Sonnet `replaceWord` with
`suggestions()` priming) from S00 stand unchanged.

## 3. Contract changes to the S00 adapter

- The highlighter is created with `active: false` and is never activated. The
  query methods (`isWordMisspelled`, `suggestions`, `replaceWord`) work while
  inactive; `inspect`, `applyCorrection`, `ignoreForSession`, and
  `personalWords` are unchanged.
- New: `misspelledRanges(text)` returns finished misspelled words as UTF-16
  `{start, end}` offsets. Tokens are runs of letters/digits/apostrophes across
  the common scripts; a surrogate half (an emoji) is not a word. A token at the
  very end of the text is treated as still being typed and is skipped.
- `enabled` continues to be `Item.enabled` (no redeclaration), so a disabled
  adapter reports `status: "disabled"` and returns no ranges.

`ComposeView` gains `errorColor`, `spellingRanges`, `spellingAdapter`,
`spellingAvailable`, `spellingStatus`, and `spellingEnabled` / `spellingLanguage`
/ `spellingPersonalWords` as temporary inputs (S04 supplies persisted settings).
It recomputes ranges on a 120 ms debounce; the debounce is only for cost — the
completeness rule is what defers the underline.

## 4. Evidence

- Underline-only: the composer was rendered offscreen with `errorColor` set to
  pure red and the body text `"this sentance has a mispelled wrod here "`. Red
  pixels occur on a single baseline row (y=187, 118 px for the three words) with
  no red pixels in the glyph body — the word text keeps the theme colour.
- Tests: adapter contract 9/9, composer integration 6/6; `test_source.sh`,
  `test_qml_names.py`, `qml-check`, `git diff --check` pass.
- Hand-tuning: `tests/spellcheck/composer-preview.qml` (real composer, mock
  shell imports).

## 5. Open for tuning

- Underline thickness is one pixel; placement is the character-box baseline.
- The inline strip is a preview affordance; its production form belongs to S02.
- Wrapped long words are drawn on their first line only.
- Checking is not yet deferred during IME composition.
