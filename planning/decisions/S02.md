# S02 decision — the spelling menu actions, made safe

Status: **READY FOR REVIEW**. Task: S02. Base: `1f9f498` (the S01 branch tip,
`task/S01-body-spelling`). Branch: `task/S02-spelling-menu`.

S01 landed the suggestion rows, Ignore, Add to dictionary, and the right-click /
`Ctrl+.` wiring as a prototype. S02 completes that prototype into the finished
menu behaviour — the only production change is a guard on the correction path
and the draft-dirty marking, plus a dedicated menu test file.

## 1. What S02 adds on top of S01

| Concern | S01 state | S02 change |
| --- | --- | --- |
| Correction target | `applyCorrection(savedPosition, replacement)` fired blindly | Re-verify the word at the saved position before editing; abort if it no longer matches |
| Draft dirty state | Menu owns focus, so the body's `onTextChanged` skipped `bodyWasEdited`/`noteUserModified` | A correction marks the draft dirty itself |
| `onSpellingAddToDictionary` | Deprecated parameter injection (`word` undeclared; qmllint/test warning) | Formal `function(word)` handler |
| Menu tests | 8 composer tests, none exercising the menu guards | `tst_spellcheck_menu.qml`, 11 focused tests |

The adapter contract is unchanged: `inspect`, `applyCorrection`,
`ignoreForSession` and `personalWords` keep their S00/S01 frozen shapes. The
guard is caller-side (in `ComposeView`), not in the adapter.

## 2. Decisions

| # | Decision |
| --- | --- |
| D1 | A correction re-checks the word at `textMenu.spellingPosition` with `inspect` and aborts unless `word` still equals `spellingWord` **and** it is still misspelled. The word-identity check is what makes the guard catch the case where the position now holds a *different* misspelled word; misspelled-ness alone is not enough. |
| D2 | A correction sets `bodyWasEdited = true` and calls `noteUserModified()`, because the menu owns focus while open and the body's own `onTextChanged` correctly declines to mark an edit it did not see. |
| D3 | "Add to dictionary" stays **app-owned** (S00 §4: `ignoreWord`, never `addWordToDictionary`), so it cannot fail in a way the menu must surface. The S02 criterion "personal dictionary failure is visible" is satisfied vacuously by construction; the only persistence — and therefore the only place a real write could fail — is S04. |

## 5. Review risks and limitations

- The stale-document guard is proven against a body replaced while the menu is
  open; the "destroyed composer" half of the S02 wording is covered by QML
  ownership (the menu is a child of the composer and cannot outlive it). No
  retained reference is held beyond the child `TextMenu`.
- "Added word survives process restart" is not S02 scope — S00 §4 made
  ignore-and-add process-global, and persistence is S04.
- No live account, mailbox, or credential was involved; all tests use the
  synthetic `mailService` fixture and reserved example domains.
